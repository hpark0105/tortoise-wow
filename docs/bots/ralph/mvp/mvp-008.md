# MVP-008: Prove exact earned state after isolated backup restore

- Epic: KAP-543
- Jira mapping: KAP-554
- Source story: TW-011
- Depends on: MVP-007
- Status: PASSED 2026-09-13 (park-head local-Qwen; evidence below)

## Allowed scope

- `docker/`
- `docs/bots/persistence-evidence.md`

## Acceptance

```gherkin
Scenario: Restore earned state into a second disposable project
Given the restart proof passed and a bounded backup exists
When that backup is restored into a separate port-free project
Then identity, ownership, XP, inventory and supported quest state match the source snapshot
```

```gherkin
Scenario: Protect the personal volume
Given source or target identity is not the expected disposable project
When restore or cleanup is requested
Then the operation stops before changing any volume
```

## Validation

- `docker compose build world`
- `./docker/backup.ps1 against disposable source`
- `./docker/test-restore.ps1 with isolated target`
- `exact state comparison`

## Result (2026-09-13)

`python docker/test_bot_restore.py -v` -> 8/8 in 226.4s across two
disposable, port-free projects (gitignored evidence: Lab A
`local/tortoise-bot-restore-a-82f3f08f56ce-20260913T102918Z`, Lab B
`local/tortoise-bot-restore-b-5ac46df00818-20260913T103100Z`).

- Lab A: Restorebot GUID:500106 earned the MVP-007 state (quest 456
  accepted from the seeded giver, 7x2031 + 4x1984 killed through normal
  combat, `quest rewarded GUID:500106 quest:456 xpBefore:630 xpAfter:800`,
  `corpse loot stored GUID:500106 item:117 before:0 after:1`), then a
  clean stop with no SIGSEGV. Snapshot S1: level 3, xp 872, money 100035,
  item 117 instance (guid 12), quest row status=1 (COMPLETE) rewarded=1
  with persisted mobcounts 7/4, ownership 1000500106 v2, roster 1. The
  lab's own db then ran `/ops/backup.sh` (the same script the personal
  server's backup.ps1 invokes), producing
  `tortoise-20260913T103051Z.sql` + sha256 sidecar in Lab A's evidence
  directory.
- Lab B (a separate project with a fresh db, sharing nothing with Lab A
  or the personal server): `/ops/restore-check.sh` (the same script the
  personal test-restore.ps1 invokes) validated the filename pattern and
  sha256, imported, and ran the bootstrap check ("Database bootstrap and
  local realm checks passed"). The row comparison then matched S1 exactly
  - identity, ownership, level/xp/money, the item 117 instance, the quest
  row, position - before the world ran. A guard run proved
  restore-check.sh rejects a filename backup.sh never produced before
  touching the db.
- Lab B world run (declared quest enabled): the restored bot re-logged
  (`[PlayerBot][Login] 'Restorebot' GUID:500106`) and resumed from the
  saved quest state (`quest init GUID:500106 quest:456 phase:3`), walked
  to the restored quest giver, and the core fail-closed on re-reward
  (`quest reward denied GUID:500106 quest:456`); no second `quest
  rewarded`, no double XP; state after the run still matched S1 exactly
  (position within 50 yd from normal wander).
- Personal-volume protection: both labs are uuid-named port-free compose
  projects (teardown verifies project labels and the absence of port
  bindings), the backup/restore scripts operate only inside the lab db
  container and the lab's evidence directory, and the personal server
  containers' StartedAt was recorded before and after the run and is
  unchanged.

Design note: a rewarded non-repeatable quest persists as COMPLETE with
rewarded=1 (Player::RewardQuest keeps the row in the quest status map), so
the restored bot correctly resumes at quest phase 3 and the core's
CanRewardQuest (already-rewarded check) rejects the turn-in; the test
asserts that fail-closed outcome rather than a second reward. Harness:
docker/test_bot_provision.py write_compose/boot_lab now accept optional
extra db volumes (docker/ -> /ops read-only; the lab evidence backups dir
-> /backups rw for the backup lab, ro for the restore lab), and the
bind/bind_abs helpers are module-level for reuse.

Gates: docker compose build world (no core change; tortoise-local:dev
sha256:f3dc289f... from the MVP-007 build), python -m py_compile for both
changed lab scripts, docker compose config --quiet, git diff --check.
Retrieval remained operator-paused (embedding container work is post-MVP);
bounded direct-read fallback only.

Use a disposable, port-free Docker project. Do not deploy or modify the personal database volume. The hosted head independently reviews source, diff, tests and acceptance.
