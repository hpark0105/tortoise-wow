# TW-012: Deterministic population boundaries

- Jira: KAP-555
- Status: passed 2026-09-13
- Depends on: TW-002, TW-009

```gherkin
Scenario: Preserve an exact requested population
Given roster capacities of zero, one, and ten
When min and max request an exact target
Then the manager logs in exactly that many distinct bots without refresh churn

Scenario: Clamp a request above capacity
Given one valid roster bot and min=max=10
When the manager normalizes the request
Then the effective range is 1..1 and only that bot is queued
```

`PlayerBotMgr` now clamps both bounds to roster capacity and preserves
`min=max`. Reconciliation compares the target with online plus loading bots,
so an asynchronous login is not queued repeatedly. Weighted selection uses
only offline candidates and valid one-based random indices.

Validation: `docker compose build world` passed with
`-DALLOW_TURTLE_ADDONS=ON`. `python docker/test_bot_population.py -v`
passed 4/4 in 238.286s across three disposable, port-free projects. The
zero target logged in none; the above-capacity one-bot case normalized to
1..1; the exact ten target logged in ten distinct bots once. No case logged
a refresh logout or crash. Evidence is under the gitignored
`local/tortoise-bot-pop-{zero,clamp,ten}-*` directories dated 2026-09-13.
