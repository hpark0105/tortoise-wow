## Result (2026-09-13)

`python docker/test_bot_restart.py -v` -> 4/4 in 132.6s on a disposable,
port-free project (gitignored evidence:
`local/tortoise-bot-restart-8af716bec00f-20260913T100008Z`). Restbot
GUID:500105:

- Earn phase: accepted quest 456 from the seeded NPC 2079, killed 7x2031 +
  4x1984 through normal PlayerBotAI combat, core auto-completed on the final
  credit, turn-in and `quest rewarded GUID:500105 quest:456 xpBefore:648
  xpAfter:818`; then killed and looted the deterministic seeded Kobold (loot
  template 990006): `corpse loot stored GUID:500105 item:117 before:0
  after:1`.
- Clean stop (SIGTERM): `[PlayerBot][Logout] 'Restbot' GUID:500105
  Acc:1000500105`, saved and halted cleanly (`Halting process...`), no
  SIGSEGV in the captured post-stop world.log.
- Restart + relogin: DB snapshot matched the pre-restart snapshot exactly -
  level 3, xp 836 (818 quest + 18 Kobold), money 100035, map 0 / zone 12,
  identical position, item 117 instance (guid 12, count 1), ownership
  1000500105 v2, roster 1; quest row persisted (character_queststatus
  status IN (1,3), rewarded=1). No [CRASH].

Two root causes fixed. (1) Lab isolation gap (docker/): the seed left
natural creatures alive around the spawn during the earn phase and a natural
hostile killed the seeded Kobold itself; with zero player damage
Creature::IsLootAllowedDueToDamageOrigin() was false, Unit::Kill cleared the
loot recipient and Player::SendLoot silently refused the corpse ("corpse
loot denied ... eligible:0 recipient:0 recipfound:0"). The DB auto-updater
was verified a no-op in the lab (146 migrations found, none executed),
excluding seed clobbering. The seed now removes natural creatures in the
spawn box before inserting the seeded pack (MVP-005 pattern), and the clean
stop is gated on both earnings (quest rewarded AND corpse loot stored)
because the quest phase machine preempts the combat loop. (2) Core shutdown
crash (src/; latent on the personal server): bot sessions are socketless, so
WorldSession::KickPlayer() is a no-op for them and World::Shutdown() left
the bot in the world; Map::UnloadAll then unloader-removed the still-online
bot Player and crashed the visibility cleanup (SIGSEGV in
Player::IsInVisibleList via Camera::UpdateVisibilityForOwner) before the
final save ran, losing the post-reward state (Kobold XP + looted item).
World::Shutdown() now calls sPlayerBotMgr.DeleteAll() (previously never
called) before KickAll(); it marks every bot PB_STATE_OFFLINE and the
existing WorldSession::Update branch then logs each bot out through the
normal save + RemoveFromWorld path in the UpdateSessions(1) call that
follows.

Test hardening: the pre-restart snapshot must contain exactly one item 117
instance (an empty-both items list is a vacuous match), the full post-stop
world.log is captured as evidence and the health test asserts it has no
"Received SIGSEGV"; _state() reads item_instance (guid, itemEntry, count by
owner_guid) because this fork's character_inventory has no item_guid column.

Gates: docker compose build world (tortoise-local:dev
sha256:f3dc289f...), python -m py_compile docker/test_bot_restart.py,
docker compose config --quiet, git diff --check. Retrieval remained
operator-paused (embedding container work is post-MVP); bounded
direct-read fallback only.
