# CMP-010: Real party membership and companion roster

- Epic: KAP-543
- Depends on: TW-014, NEXT-001
- Status: ready

```gherkin
Scenario: Recruit an owned companion into the player's party
Given an online human owner and an online owned companion
When the owner recruits the companion
Then the normal Group system contains both players
And the human remains leader
And the binding survives companion logout and recall

Scenario: Reject an unsafe roster change
Given combat, a full party, a foreign owner, or a stale roster sequence
When recruit, dismiss, or recall is requested
Then the request is rejected without changing the group or ownership rows
```

Implement recruit, dismiss and recall for one companion first. Use normal
group membership as gameplay state and `bot_ownership` as durable authority.
Do not add role tactics, LLM calls, teleport recall or party-size changes.

Validation uses a disposable owner, companion and intruder and checks normal
Group state, owner-only control, full-party rejection, logout/recall and stale
sequence rejection.
